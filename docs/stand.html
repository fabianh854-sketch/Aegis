Wo wir stehen

v0.0.9 – Härtung und Bugfixes

Session mit gehaltenem Schlüssel, Argon2-Grenzen, atomares Speichern mit Backup, Zwischenablage ohne Windows-Verlauf, Passwortwechsel nur mit altem Passwort, Mindestlänge 12.

v0.1.0 – Oberfläche

Ersteinrichtung „Master-Passwort festlegen“, Ladeanzeige (Argon2 im Hintergrund), Seitenleiste eingeklappt mit Knopf in der Titelleiste, neu gezeichnete Symbole (Zahnrad, Tür), App-Icon und Mini-Schild.

v0.2.0 – Sichere, signierte Updates

aegis-updater.exe (einziger Teil mit Netz, nur über Windows-curl.exe), signiertes Manifest (minisign), Downgrade-Schutz, kumulativer Sicherheitsstatus, Ablauf nach 7 Tagen, Hinweisleiste in der App, lokale Release-Skripte. Ende-zu-Ende gegen GitHub getestet: Testkopie 0.1.9 fand v0.2.0, prüfte die Signatur, ersetzte beide Dateien und startete neu.

Wo wir weitermachen

1. PR #5 mergen offen

Damit künftige Releases oben automatisch erklären, welche Datei man herunterlädt.

2. Wöchentlich Manifest erneuern bis 22.11.

Sonst zeigt Aegis „Update-Status nicht bestätigt“.

pwsh scripts\refresh-manifest.ps1

3. Schlüssel absichern wichtig

%USERPROFILE%\.aegis-signing\aegis.key offline sichern (z. B. USB-Stick), Passwort getrennt aufbewahren. Zwei-Faktor-Anmeldung bei GitHub aktivieren.

4. Konzept Schlüsselverlust deine Entscheidung

Ersatzschlüssel, Wechselweg, Vorgehen bei Diebstahl. Im Code vorbereitet: TRUSTED_KEYS ist eine Liste.

5. egui/eframe-Upgrade eigenes Projekt

Von 0.29 auf aktuell. Entfernt die beiden Ausnahmen in deny.toml (paste, ttf-parser), bringt aber viele UI-API-Änderungen.

6. E-Mail in Commits optional

Für künftige Commits die GitHub-noreply-Adresse setzen und „Keep my email addresses private“ aktivieren.
