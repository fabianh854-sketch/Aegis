# Aegis Härtung Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sicherheitslücken und Bugs in Aegis schließen, ohne neue Funktionen und ohne Änderung des Dateiformats v1.

**Architecture:** `aegis-core` bekommt eine `Session` (gehaltener Schlüssel, Header, Vault), geprüftes Header-Parsing und robustes atomares Schreiben mit Backup. `aegis-app` bekommt einen `ClipboardGuard` mit austauschbarem Backend (testbar ohne echte Zwischenablage). `app.rs` wird darauf umgestellt; die Optik bleibt.

**Tech Stack:** Rust stable 1.96, eframe/egui 0.29, argon2 0.5, chacha20poly1305 0.10, zeroize 1, arboard 3.6 (neu als direkte Abhängigkeit, bereits im Lockfile).

**Spec:** `docs/superpowers/specs/2026-11-14-haertung-design.md`

## Global Constraints

- Dateiformat bleibt v1: `MAGIC(4)="AEGS" | VERSION(1)=1 | m(4) | t(4) | p(4) | SALT(16) | NONCE(24) | CIPHERTEXT`, Header (57 Byte) ist AAD.
- Bestehende Tresore müssen sich mit dem bisherigen Passwort öffnen lassen.
- Keine neuen Crates außer `arboard` (und optional `subtle`, beide schon im `Cargo.lock`); `cargo deny check` muss bestehen.
- Argon2-Grenzen beim Laden: `1 ≤ m_cost ≤ 1_048_576`, `1 ≤ t_cost ≤ 16`, `1 ≤ p_cost ≤ 16`, Prüfung vor der Ableitung.
- Mindestlänge neues Master-Passwort: 12 Zeichen (Unicode-Zeichen, nicht Bytes); gilt nur für Anlegen und Ändern.
- Zwischenablage leeren nach 30 s; nur wenn noch unser Wert drin ist; bei Sperren/Beenden auch bei nicht lesbarer Zwischenablage leeren; alles nur, wenn die Einstellung aktiv ist.
- UI-Texte Deutsch. Keine Fehler still schlucken.

## Review Focus

- Kurze/abgeschnittene Datei oder falsches MAGIC → `AegisError::Format`, keine Panik (Test in Task 1).
- Speichern schlägt fehl (z. B. Zielordner weg) → `Err`, `session.vault()` unverändert (Test in Task 3).
- Tresor ohne Einträge: anlegen, schließen, öffnen funktioniert (Test in Task 3).
- Zweimal schnell kopieren → der Timer des ersten Kopierens löscht den zweiten Wert nicht vorzeitig (Test in Task 4).
- Master-Passwort mit Umlauten: 12 Zeichen erlaubt, 11 Zeichen abgelehnt, obwohl > 12 Byte (Test in Task 5).

**Interfaces:**
- Consumes: `Header`, `HEADER_LEN` (Task 1); `write_atomic`, `create_new`, `backup_path` (Task 2); `crypto::{derive_key, seal, open, random_bytes}`.
- Produces:
```rust
pub struct Session { path: PathBuf, header: Header, key: Zeroizing<[u8; KEY_LEN]>, vault: Vault }
impl Session {
    pub fn create(path: &Path, master: &[u8], params: &KdfParams) -> Result<Session, AegisError>;
    pub fn open(path: &Path, master: &[u8]) -> Result<Session, AegisError>;
    pub fn vault(&self) -> &Vault;
    pub fn path(&self) -> &Path;
    pub fn commit(&mut self, candidate: Vault) -> Result<(), AegisError>;
    pub fn change_master(&mut self, current: &[u8], new: &[u8], params: &KdfParams) -> Result<(), AegisError>;
}
```
- `create`: Salt+Nonce zufällig, Datei per `create_new`. `commit`: gleicher Salt/Parameter, **neue Nonce**, `write_atomic`, `self.vault = candidate` erst nach Erfolg. `change_master`: `derive_key(current, salt, params_alt)` konstantzeitig mit `self.key` vergleichen (sonst `WrongPassword`, nichts geschrieben); neues Salt, neue Parameter, `write_atomic`, danach `.bak` mit dem neuen Dateiinhalt überschreiben; Header/Key erst nach Erfolg übernehmen. `Session` implementiert `Debug` nicht (Schlüssel). `Zeroizing` + `ZeroizeOnDrop` des Vaults erledigen das Nullen.

### Task 4: `ClipboardGuard`

**Files:**
- Create: `crates/aegis-app/src/clipboard.rs`
- Modify: `crates/aegis-app/Cargo.toml` (`arboard = { version = "3.6", default-features = false }`), `crates/aegis-app/src/main.rs` (`mod clipboard;`)

**Interfaces:**
```rust
pub trait Backend {
    fn set_secret(&mut self, text: &str) -> Result<(), ()>; // Windows: set().exclude_from_monitoring().text()
    fn read(&mut self) -> Option<String>;                    // None = nicht lesbar
    fn clear(&mut self) -> bool;
}
pub struct SystemClipboard; // impl Backend über arboard; Clipboard::new() je Aufruf, Fehler → Err/None/false
pub struct ClipboardGuard<B: Backend> { backend: B, held: Option<Zeroizing<String>>, clear_at: Option<Instant> }
impl<B: Backend> ClipboardGuard<B> {
    pub fn new(backend: B) -> Self;
    /// Ok = geschützt kopiert. Err = Backend fehlgeschlagen: Aufrufer kopiert per ctx.copy_text und zeigt Hinweis;
    /// der Wert wird trotzdem gemerkt. `clear_after: None` = nicht automatisch leeren (Einstellung aus).
    pub fn copy(&mut self, text: &str, clear_after: Option<Duration>, now: Instant) -> Result<(), ()>;
    /// Nach Ablauf: read()==held → clear; read() anderer Text → vergessen; read() None → nächster Versuch in 1 s.
    /// Rückgabe: wann erneut prüfen (für request_repaint_after), None wenn nichts ansteht.
    pub fn tick(&mut self, now: Instant) -> Option<Duration>;
    /// Sperren/Beenden: read() anderer Text → vergessen; gleich oder None → clear. Danach nichts gemerkt.
    pub fn clear_now(&mut self);
}
```
- `exclude_from_monitoring()` statt einzeln Verlauf/Cloud: laut arboard-Doku die empfohlene Kombination beider Ausschlüsse (Spec-Absicht unverändert). Auf Nicht-Windows-Zielen per `#[cfg(windows)]` ohne Ausschluss kompilieren.

### Task 5: `app.rs` auf Session und Guard umstellen, UI-Bugs

**Files:**

**Interfaces:**
- Consumes: `Session` (Task 3), `ClipboardGuard<SystemClipboard>` (Task 4), `AegisError::{AlreadyExists, WrongPassword}`.
- Produces (in `app.rs`, privat, getestet): `fn validate_new_master(new: &str, confirm: &str) -> Result<(), &'static str>` — leer → „Bitte ein neues Passwort eingeben“, `< 12` Zeichen → „Mindestens 12 Zeichen“, ungleich → „Die Passwörter stimmen nicht überein“.

Änderungen:
- Felder `vault` + `master` → `session: Option<Session>`; `clipboard_clear_at` → `clipboard: ClipboardGuard<SystemClipboard>`.
- `path: PathBuf` → `path: Result<PathBuf, String>`: fehlt `APPDATA`, Fehlertext „APPDATA nicht gesetzt – Speicherort unbekannt“ auf dem Entsperren-Bildschirm, Entsperren/Anlegen deaktiviert.
- `password`, `confirm`, `new_master`, `new_master_confirm`, neu `current_master`, `gen_password` → `Zeroizing<String>`.
- Anlegen: `validate_new_master(password, confirm)`, dann `fs::create_dir_all` (Fehler anzeigen, nicht ignorieren), `Session::create(path, pw, &KdfParams::default())`. Öffnen: `Session::open`.
- `commit` nutzt `session.commit(candidate)`.
- Master ändern: drittes Feld „Aktuelles Passwort“ zuerst; `validate_new_master`; `session.change_master(current, new, &KdfParams::default())`; `WrongPassword` als Status anzeigen. Alle drei Felder danach leeren.
- Kopieren (Editor + Generator): `clipboard.copy(text, settings.clear_clipboard.then_some(CLIPBOARD_CLEAR_AFTER), now)`; bei `Err` `ctx.copy_text(text)` und Status „Kopiert – Verlauf konnte nicht ausgeschlossen werden“ (kein Fehler-Rot nötig).
- `update`: `if let Some(d) = clipboard.tick(now) { ctx.request_repaint_after(d) }`.
- `lock()`: `if settings.clear_clipboard { clipboard.clear_now() }`, alle Zeroizing-Felder leeren. `impl eframe::App::on_exit(&mut self, _: Option<&eframe::glow::Context>)` (Signatur laut eframe 0.29 prüfen): gleiche Clipboard-Regel.
- Editor: `Editor.original: Entry`; Abbrechen bei `entry != original` (Vergleich der vier Felder) zweistufig: Text „Änderungen verwerfen?“ statt „Abbrechen“, zweiter Klick verwirft.
- „Unlock Vault“ → „Tresor entsperren“. Einstellungen „Speicherort“: echter Pfad (`path.display()`), bei langen Pfaden mit `truncate()`/Hover-Text.
